# lfd_realsense — порядок работы

Обучение манипуляционного робота демонстрацией по данным RGB-D камеры.
Оператор один раз показывает действие с объектом, система извлекает из записи
пару «признаки объекта → последовательность действий» и строит политику.

Ниже — полная последовательность от подготовки рабочей зоны до инференса.

---

## 0. Что должно быть установлено

```bash
pip install pyrealsense2 opencv-contrib-python numpy pyyaml scikit-learn ultralytics mediapipe
```

`opencv-contrib-python` (не обычный `opencv-python`) — иначе не будет модуля
`cv2.aruco`.

Все команды запускаются **из корня репозитория**.

---

## 1. Подготовка рабочей зоны

Один раз перед серией записей.

1. **Камера.** Intel RealSense D435i монтируется стационарно над рабочей зоной,
   объектив вниз, высота ≈ 80 см. После начала записей камеру двигать нельзя:
   алгоритм считает смещение объектов в системе координат камеры, и сдвиг
   камеры будет истолкован как перемещение объектов.

2. **Контейнеры.** Приёмные контейнеры с маркерами ArUco, словарь
   `DICT_4X4_50`, размер маркера 4 см (задано в `config/perception.yaml`,
   секция `aruco: marker_size_m`). Используемые ID контейнеров: **1, 2, 3**
   (`config/demos.yaml`, `global: container_ids`). Маркер должен быть целиком
   виден камере и не перекрываться рукой в момент завершения действия.

3. **Объекты.** Классы, которые знает детектор (`CLASS_TO_ALPHA` в
   `scripts/demo_parser.py`):
   `cube_blue`, `cube_red`, `cube_green`, `cup_silver`, `cup_dark_grey`,
   `washer_green`, `lid`.
   Новый тип объекта потребует дообучения YOLO — это отдельная процедура,
   в этот цикл не входит.

4. **Освещение.** Постоянное. Детектор начала движения реагирует на изменение
   яркости: включение/выключение света или тень от проходящего человека даст
   ложное срабатывание.

### Снять параметры камеры (один раз)

```bash
python scripts/dump_intrinsics.py --demos data/demos
```

Скрипт напечатает блок `camera:` — его нужно **дописать в конец
`config/perception.yaml`**. Он же положит `intrinsics.json` в корень `config/`
и в каждую существующую папку демонстрации.

Повторять только при смене камеры или разрешения потока.

## 2. Запись демонстраций

На каждый тип объекта — одна демонстрация.

```bash
python scripts/record_demo.py demo_cube_blue_001
```

Запись сохраняется в `data/demos/demo_cube_blue_001/`.

**Управление окном:**

| Клавиша | Действие |
|---|---|
| `SPACE` | первое нажатие — старт записи, второе — стоп и сохранение |
| `Q` | выход (если запись идёт — остановит и сохранит) |

**Протокол одной записи:**

1. Положить объект в рабочую зону, руки убрать из кадра.
2. Нажать `SPACE` — пошла запись. Дать сцене 1–2 секунды покоя: первые кадры
   используются как фон для детектора движения.
3. Выполнить действие: взять объект и переместить в нужный контейнер
   (либо накрыть крышкой, либо отправить дальше мимо контейнеров).
4. **Убрать руку из кадра полностью** и дать сцене замереть на 1–2 секунды.
   Это важно: конечное состояние сцены снимается по кадрам после остановки
   движения, и рука в кадре испортит детекции.
5. Нажать `SPACE` — запись остановлена.

**Что получается в папке демо:**

```
data/demos/demo_cube_blue_001/
├── rgb/00000.png, 00001.png, ...     — цветные кадры
├── depth/00000.png, ...              — карта глубины (uint16)
├── timestamps.csv                    — метки времени
├── intrinsics.json                   — параметры камеры
└── rgb.mp4                           — видео для просмотра
```

**Замечание.** Зелёный скелет руки в окне превью — только визуальная подсказка
оператору (видна ли рука). В файлы он не пишется и при разборе демонстрации
не используется.

### Зарегистрировать запись в конфиге

Открыть `config/demos.yaml` и дописать в секцию `demos`:

```yaml
  - id: demo_cube_blue_001
    path: "data/demos/demo_cube_blue_001"
    object_class: cube_blue      # эталон для проверки, что YOLO узнал объект
```

`action_sequence` здесь **не задаётся** — действие извлекается из видео
автоматически. `object_class` нужен только для верификации.

## 3. Проверка разбора демонстраций

Прежде чем обучать политику, убедиться, что из записей извлеклось то, что нужно:

```bash
python scripts/demo_parser.py --config config/demos.yaml
```

В выводе по каждой демонстрации:

```
[✓ OK] demo_cube_blue_001
  object_class (конфиг) : cube_blue
  alpha (извлечён)      : shape=cube, color=blue  [✓]
  action_seq            : MOVE(container_1)
```

**На что смотреть:**

- `alpha` должен совпасть с `object_class` — метка `[✓]`. Если `[✗ РАСХОЖДЕНИЕ]`,
  YOLO определил не тот объект.
- `action_seq` должна соответствовать тому, что реально показывали.
- Появился `PASS` вместо ожидаемого действия — алгоритм не увидел значимого
  смещения; чаще всего порог смещения не подходит либо конечное состояние снято
  с рукой в кадре.

Подробный лог с промежуточными величинами (смещения объектов, расстояния до
контейнеров, счётчик крышек):

```bash
python scripts/demo_parser.py --config config/demos.yaml --debug
```

Если объект не детектируется — посмотреть глазами, что видит YOLO:

```bash
python scripts/debug_detections.py --demo demo_cube_blue_001 --mode video
```

Результат — mp4 с нарисованными рамками в `debug_out/`.

### Пороги

В `config/demos.yaml`, секция `global`:

| Параметр | Смысл |
|---|---|
| `move_threshold_m` | минимальное смещение объекта, считающееся действием |
| `max_container_dist_m` | расстояние до контейнера, при котором объект считается в него помещённым |
| `motion_threshold_px` | сколько пикселей должно измениться, чтобы считать это движением |
| `min_sustained_frames` | сколько кадров подряд движение должно держаться |
| `alpha_frames` | сколько кадров усредняется для начального состояния |
| `final_frames` | то же для конечного состояния |

Пороги смещения заданы **в метрах**. Подбирать по фактическим значениям
из вывода `--debug`.

## 4. Обучение политики

```bash
python scripts/build_policy.py --validate --tree
```

Что происходит: разбор всех демонстраций → обучение дерева решений на парах
`(shape, color) → action_sequence` → сохранение в `policy/policy.pkl`.

- `--validate` — leave-one-out проверка: каждая демонстрация по очереди
  исключается из обучения, политика обучается на остальных и проверяется на ней.
  **Это и есть источник цифр для оценки обобщения.**
- `--tree` — печатает структуру дерева.

Посмотреть, что политика знает, и проверить предсказание на произвольном
дескрипторе:

```bash
python scripts/policy_trainer.py --predict cube yellow
```

Добавление нового правила = записать демонстрацию, дописать её в `demos.yaml`,
перезапустить `build_policy.py`. Код при этом не меняется.

## 5. Инференс

**На живом потоке камеры:**

```bash
python scripts/policy_runner.py --live
```

**На сохранённой паре кадров:**

```bash
python scripts/policy_runner.py \
    --image data/demos/demo_cube_blue_001/rgb/00050.png \
    --depth data/demos/demo_cube_blue_001/depth/00050.png
```

В окне выводится распознанный дескриптор объекта, предсказанная
последовательность действий и 3D-координаты объекта и целевого контейнера.

В логе должно быть `Intrinsics загружены: fx=... fy=...`. Если написано
`Intrinsics не найдены в config — 3D недоступен`, значит секция `camera:`
не добавлена в `config/perception.yaml` (см. шаг 1).

## Краткая шпаргалка

```bash
# один раз при развёртывании
python scripts/dump_intrinsics.py --demos data/demos
#   → блок camera: вставить в config/perception.yaml

# на каждый новый тип объекта
python scripts/record_demo.py demo_<объект>_001
#   → дописать запись в config/demos.yaml

# проверить, что разобралось правильно
python scripts/demo_parser.py --config config/demos.yaml --debug

# обучить политику
python scripts/build_policy.py --validate --tree

# запустить
python scripts/policy_runner.py --live
```

## Типичные проблемы

| Симптом | Причина |
|---|---|
| `action_seq: PASS` при реальном действии | смещение ниже `move_threshold_m`; либо рука в кадре в конце записи |
| `FORWARD` вместо `MOVE(container_N)` | маркер контейнера не виден в конечных кадрах либо объект дальше `max_container_dist_m` |
| `alpha` не совпал с `object_class` | ошибка детектора; проверить через `debug_detections.py` |
| `Intrinsics не найдены` | нет секции `camera:` в `config/perception.yaml` |
| `pixel_to_3d: нет валидных depth-значений` | объект вне рабочего диапазона глубины, бликует или перекрыт |
| Движение не найдено, `onset = 0` | изменение слишком слабое: поднять контраст сцены или снизить `motion_threshold_px` |

## Структура репозитория

```
config/
  demos.yaml            перечень демонстраций и пороги
  perception.yaml       веса YOLO, параметры ArUco, секция camera
perception/
  geometry.py           проекция пикселей в 3D (общая для офлайн и онлайн)
  detector.py           обёртка YOLOv5
  aruco_tracker.py      детекция маркеров контейнеров
  postprocessor.py      3D-координаты объектов, верификация класса
  frame_processor.py    сборка потока с камеры
  weights/best.pt       веса детектора
scripts/
  dump_intrinsics.py    снятие параметров камеры
  record_demo.py        запись демонстрации
  demo_parser.py        разбор записи → (дескриптор, действия)
  policy_trainer.py     обучение дерева решений
  build_policy.py       полный цикл: разбор → обучение → policy.pkl
  policy_runner.py      инференс
  debug_detections.py   визуальная проверка детекций
policy/
  policy.pkl            обученная политика
data/demos/             записанные демонстрации
```
